Naming performance

Naming now reaches the 30 FPS target in the tested 480x360 idle, cursor and editing cases, with identical rendering.

At 480x360/8 MiB, idle improves from 16.51 to 29.90 game FPS and 60.56 to 9.83 ms mean frame work. Cursor movement improves from 16.48 to 30.00 FPS; editing measures 30.22 FPS. Idle CPU canvas painting drops from 49.70 to 0.243 ms on average, including periodic blink redraws. At 320x240/4 MiB, idle work falls from 31.46 to 9.03 ms while pacing remains near 30 FPS.

The keyboard retains its existing image. The first frame uses the unchanged full painter. Subsequent frames redraw the name strip only when the value, length or insertion blink changes; cursor movement redraws only the old and new key/action cells. A clean keyboard image is reused. The player model, its idle pose and the surrounding 3D view continue to render on every frame. Input, naming limits, text, layout and configuration are unchanged. No additional production image is allocated.

The previous RDP read is fenced before any CPU canvas write, dirty pixels are written back before the next blit, and every composition still waits before returning. Both modes pass 768 CPU comparisons against the original painter and 24 pairs of actual completed full RDP framebuffers, byte for byte. Tests cover every cursor position, name length and blink state plus actual append/delete/space/end/default operations and all supported capacities. Identical state explicitly causes no repaint; existing naming input/anchor checks pass. Independent read-only review found no blocker.

Each case retains assets, warms 32 frames, and samples 32 quiet frames. Cursor and editing cases change at the production repeat cadence of seven game frames. Both resolutions use the same immutable ROM and fixed SDK queue; real title music is mixed. A frozen shipped frontend/font object excludes concurrent duel UI changes. The measured free heap is 1,296,840 bytes at 4 MiB and 4,144,904 bytes at 8 MiB after diagnostic scratch images are released.

These are ares N64 CP0 measurements with emulated RSP and host-backed RDP waits, not physical-console FPS. Frame work excludes display acquisition/pacing wait. Common presentation and audio costs remain included; controller polling/VM work and input-triggered SFX setup are outside the callbacks. Brief sampler averages above 30 FPS reflect acquisition/measurement phase; the production target remains 30. Prior comprehensive performance and dialogue reports are preserved separately.
