The dialogue cache reaches the 30 FPS target in the tested Sam conversation and choice screens without changing their pixels.

At 480x360, a fully revealed panel improves from 21.30 to 30.01 game FPS (46.93 to 24.27 ms work). The three-choice screen improves from 18.34 to 29.99 FPS (54.52 to 25.09 ms). Full-panel CPU paint drops from 21.36 ms to 0.085 ms; RDP composition remains about 0.87 ms. This identifies repeated CPU canvas painting, rather than the character models, as the avoidable cost in these views.

Each modal retains its existing panel and popup images. Unchanged panels and cursors reuse those pixels. Typewriter text appends only newly visible compact glyph runs; page changes, backwards reveal, speaker or hint changes use the original complete painter. Choice popups repaint when the selection changes. The world and actors continue to render every frame. Cache writeback occurs only after CPU changes; every composition still waits for its RDP read before the canvas may be modified or freed. No extra image memory is allocated in production.

Both 320x240/4 MiB and 480x360/8 MiB pass 480 CPU state comparisons against the original painter plus 24 pairs of actual completed RDP framebuffers. Checks cover incremental reveal, rewinds, page/speaker/hint changes, static reuse and cursor changes. All bytes match. Original long-text pagination and advance/reveal rules also pass. Each timing case uses 32 warmup frames and 32 sampled frames with the same immutable ROM; the frontend/font object is the shipped 3d53 version, excluding concurrent generic-UI experiments.

These are ares N64 CP0 timings, with emulated RSP work and host-backed RDP waits, not physical-console FPS. The prior comprehensive 124-scenario baseline is preserved separately. Naming remains 16.47 FPS at 480 in this gate and is an additional UI optimization target.
