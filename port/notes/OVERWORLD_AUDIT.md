# Out-of-duel port audit

The source inventory is generated by `python3 port/tools/audit_overworld.py` into
`overworld_inventory.json`. It enumerates **35 script files, 237 `Script_*`
entry labels, 43 `Preload_*` labels, and 104 script command indices**, plus every
non-duel `src/engine` module. These are source inventory counts, not claims that
every state or feature has been tested.

## Architecture that must be preserved

`src/data/map_scripts.asm` gives eight entry points for each of the 34 maps:
NPC definitions, post-NPC, objects, unhandled A press, map load, after duel,
player movement, and map load/textbox close. The objects and movement entries
matter as much as talking to an NPC. A bytecode-only implementation misses
native instructions before `start_script`, assembly after `end_script`, and
native conditional preload wrappers.

Story commands and their exact byte lengths are defined by
`src/macros/scripts.asm`; their implementations are in
`src/engine/overworld/scripting.asm`. Event IDs are in
`src/constants/script_constants.asm`; the 119 IDs alias bitfields in 64 bytes,
through `EventVarMasks`. Individual flags and aggregate flags intentionally
share the same bits. They must not be stored as independent values.

NPC starting coordinates/directions, preloads, names, interaction script, and
opponent deck are separate data sources: `npc_map_data.asm`, `npcs.asm`, and
`map_scripts.asm`. Conditional NPCs in `port/maps/npcs/` are shown together for
reference; they do not all coexist in the game. The image alone cannot decide
which NPCs to show. NPC sprites are 2x2 map tiles; player movement advances two
tiles, not one.

The runtime has to dispatch a completed duel through the map's after-duel
entry. Merely adding a medal or opening a booster on a win loses scripted
movement, dialogue, pupil relocation, tournament advancement, and legendary
sequence state. The original uses zero for a story duel win; the host duel
adapter's result convention must be converted explicitly.

## Implemented portable support and verification

`port/gameplay/` implements collection ownership, all card metadata, starters,
deck validation/build/dismantle, sixty recipes, fifty Auto Deck recipes, exact
booster generation, Card Pop card selection/history, fifteen PC mails and
their text/reward tables, and Challenge Machine state/selection/records. The
data is extracted from the linked disassembly by `gen_data.py` and checked in
as C tables. It has no runtime dependency on a Game Boy ROM or CPU emulator.

`GpState` is6074 bytes on the tested host ABI. `GP_SAVE_SIZE` is6082 bytes,
explicitly serialized little endian with a version signature and CRC32. Decode
is transactional and checks counts, IDs, decks, challenge counters, and length.
It does not replace the frontend's journal or power-loss-safe storage.

Verification commands:

```sh
make -C port/gameplay test
make -C port/gameplay differential
```

The first covers all29 pack variants x256seeds,50 recipes,3 starters, ownership
and album limits, duplicate-name deck rules, Card Pop history/parity, all15
mails,256 Challenge Machine sequences, streak continuation/loss, and save
roundtrip/corruption/truncation rejection.

The differential test runs the original SM83 `GenerateBoosterPack` for every29
pack variant x32seeds. All ten card IDs, the final three RNG bytes, and all256
collection bytes match. The GB core is only a test oracle. This is stronger
evidence for booster fidelity than generic rarity/size assertions.

The same differential test additionally verifies256 Challenge Machine opponent
sequences and256 Card Pop selections, including the resulting RNG bytes.
Peer transaction tests verify both players' Card Pop histories/rewards,
validation before a gift changes either state, receiver capping, and saved
recipe copying without introducing owned cards. Player-name encoding matches
the original full-width `MARK` bytes and stores the two original identity salts.

`port/overworld/tests/native_helpers.c` checks all native RAM aliases and
postincrement/decrement access, Tech5's `inc [hl]` preload, writable Challenge
Cup opponent history, original medal-mail order, and65K RNG draws against the
portable RNG already exercised by the differential booster test.

These checks do not establish overall story or N64 frontend completion. Each
feature's frontend, input, rendering, save hooks, and continuation behavior
still need their corresponding end-to-end checks.

`port/frontends/n64/adventure/extra_ui.c` now provides the original five PC
choices, mailbox slot/ID mapping, both mail text pages with player-name
substitution, one-time reward display, all18 glossary topics, all35 credits
text entries with original NPC scene placements and chronological master order,
and printable card/deck/collection reports. Printer output is an explicit N64
adaptation: paginated preview plus a new text note on a formatted Controller
Pak; it does not implement a Game Boy Printer cable protocol or format/delete
other notes. `tools/test_extra_ui.sh` exercises mailbox insertion order,
two-pack rewards, named text, glossary/credits coverage, restoration of the
world after credits, and the exported Controller Pak report contents through
a host mock. Physical Controller Pak export remains a hardware check.

`adventure/tools/test_profiles.sh` compiles the actual `profiles.c` and
`save_sram.c` with scripted menus and a cartridge DMA mock. It checks two
canonical diaries alongside duel/settings files, salted player identities,
persisted RNG and play time, Card Pop duplicate rejection and both-player
rewards, Gift Center directions0/1/2/3 with profile1 or2 active, recipe transfer
without creating cards, selected physical decks supplied to Battle Center,
and controller2/pending-duel guards. Partial DMA at each commit stage and all33
possible byte prefixes of the final header recover both old diaries or both
new diaries; no mixed pair is accepted. Link battles intentionally do not
produce resumable duel saves, matching the original rejection of link-duel
continuation.

## Native-adapter defects found and corrected during this port

- Replaced an initial xorshift RNG with the original three-byte RNG and
  multiply-high bounded selection.
- Replaced dropped writes through `[hl]` with exact RAM-address adapters,
  including preload X/Y changes and the four-byte Challenge Cup bitfield.
- Replaced unknown-memory aliasing with a concrete error.
- Fixed `GetCardName` to return its text ID in DE, allowing subsequent native
  writes into the correct text RAM slots.
- Preserved separate `wTxRam2`, `wTxRam2_b`, `wTxRam3`, and `wTxRam3_b` slots.
- Checked the exact medal-mail order and event aggregation.
- Identified eager reads of an `ld [hli],a` destination, which would increment
  the pointer twice; the native interpreter now avoids that destination read.

The audit also identified native Man1 request selection, legendary selection
without replacement, start-map trigger flow, save endian layout, and native
source-address alignment as required review points for the story engine.
