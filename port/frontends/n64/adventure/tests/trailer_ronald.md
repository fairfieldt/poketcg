# Private Ronald trailer checkpoint

`trailer_ronald_stage.c` runs an ordinary human player using the original Squirtle & Friends deck against the source final Legendary Ronald encounter. A deterministic frontend policy reaches a legal turn, keeps the engine's exact `host->save` bytes, and continues that save using the recorded answers. It verifies the full saved-state hash and request type/menu/owner/shown side at every resumed choice. No card, HP, attachment, flag, RNG or save byte is patched.

The selected seed is 8 (`rng={8,0,0x5a}`), turn counter 4, six Prizes remaining on each side. MARK's Staryu Lv15 can use Slap for 20 damage against Ronald's already damaged Dratini with 10 HP. The real engine knocks Dratini out, awards one Prize, then Ronald promotes Zapdos Lv68. This is mid-battle, not the end of the duel.

The source encounter is `src/scripts/pokemon_dome.asm`'s six-Prize Legendary Ronald duel with `MUSIC_DUEL_THEME_3` (4). `LEGENDARY_RONALD_DECK_ID` is 27/0x1b; the deck table's index 29 is a different numbering scheme.

The host generator was built against the existing native-host engine objects and optional effects/AI objects. Link `trailer_ronald_stage.c` with the objects in `n64/build/host/engine/` and the paths listed by `n64/build/host/optional.lst`; it supplies its own fatal callback. Invoke `stage OUTPUT_DIRECTORY` after creating that private directory. The verified outputs currently live in ignored `adventure/build/trailer-ronald/`:

- `ronald.duel`: 1,660 original save bytes, SHA-256 `990334314b7bbec9a49b393fb6bd8bd2638e1326f01b383cf5ea42a2f9aba5b4`.
- `transcript.txt` and `answers.json`: actual resumed engine events/choices and state hashes.
- `buttons.json`: proposed 14-second controller sequence, measured from the first displayed action menu. The timing is a capture starting point; it has not been run in Ares.

For a private capture ROM, include `trailer_ronald.c` and its header, place the generated bytes at `rom:/trailer/ronald.duel`, and call `trailer_ronald_load(&setup,saved)` after normal runtime initialization. Then call the unchanged production `n64_duel_play(&setup,saved)`. The loader validates the save and encounter. The capture entry point owns video/audio initialization, private save-directory isolation, counter hiding and its output shader; this module changes none of them.

Native controller path from the verified continuation:

| Beat | Input on controller 1 | Real request / result |
| --- | --- | --- |
| Establish board | Hold about 1.4 s | Action menu starts on Hand (cursor 0) |
| Select attack | Down, release, A | Attack is action 1 |
| Choose Slap | A | Only one printed attack, index 0 |
| Begin attack | A | “Staryu Lv15's Slap!” acknowledgment |
| Show knockout | A after the damage flash | “Dratini was Knocked Out!” |
| Show Prize prompt | A | “MARK will draw 1 Prize(s).” |
| Take Prize | A | First remaining Prize, index 0 |
| Show card | A after a visible hold | Real Prize card screen |
| Show replacement | A | Ronald places Zapdos Lv68 |
| End on board | A | Ronald's turn; stop around 14 s |

Each button should be a fresh two-VI-tick press with a released gap. The reference timing proposal holds attack/KO/Prize screens for roughly 1–2 seconds each. Prefer advancing by the logged request sequence when the private controller wrapper can observe it.

Only source/host work was performed here. No native emulator, production entry point, shared Makefile, live Steam session or user save was changed. Capture must use the requested genuine CRT Guest Advanced shader with `interm=0`; no counter burn-in or shader preview image is supplied by this fixture.
